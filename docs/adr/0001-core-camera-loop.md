# ADR 0001: 固定視点で探し、長押し露光／解放で写真を確定する

- Status: Accepted（実装前、2026-10-30）
- 対象: ゲームの核、カメラの操作、制作範囲
- 現行仕様: [../SPEC.md](../SPEC.md)

## 背景

SLAPJAM #2のテーマはSpeed、縦画面スマホのHTML5ゲームを48時間で作る。プレイヤーが繰り返し触りたくなる機械式シャッターの反応と、幽霊を捉える遊びを優先したい。自由移動の探索や、本物のカメラ全機能を実装すると、撮影体験の調整時間を削る。

## 採用した判断

1. 撮影者は教室内の一点に立ち、スマホ画面ドラッグで視点だけを振る。撮影が始まると構図が固定される。
2. シャッターは長押しで露光し、解放で直ちに撮影内容を確定する。レンズシャッター風の6枚羽根が約80msで閉じる物理的な見え方を中心演出にする。
3. 超常カメラなので、露光中でも被写体の蓄積像がビューファインダーに可視化される。写真はこの蓄積像と同じ時刻履歴から生成する。
4. 幽霊の速さで光の蓄積とブレが変わり、適正な撮影時間が異なる。撮影の巧拙は固定の秒数当てでなく可視率・ブレ・構図で判断する。
5. 1つの教室で3幕を構成し、失敗時は即再試行、最後は実際に撮った3枚のアルバムを見せる。

## 比較して採用しなかった案

- **自由歩行する一人称ホラー**：空間探索、当たり判定、迷子対策、操作ボタンが増える。シャッターに触る頻度が下がる。
- **タップだけで一瞬の霊を撮る反射神経ゲーム**：Speedは直感的だが長時間露光という個性が消え、シャッターを「閉じる瞬間」の選択が薄くなる。
- **露光時間を事前にダイヤル設定してから撮影する本物風カメラ**：カメラらしいが結果が出るまでの待ち時間が増え、ライブの駆け引きを弱める。
- **完全な物理ベースの撮影シミュレーション**：計算量と調整項目が増える。プレイヤーの見た目と判定を一致させる簡素な蓄積表現を選ぶ。
- **制限時間・HP・フィルム枚数による罰**：リトライを躊躇させる。今作の価値は気持ちよく何度も撮影することなので見送る。

## 影響とトレードオフ

- 長押し中は視点変更できず、構図を決める探索フェーズと撮影フェーズが明確になる。その代わり操作は単純で、スマホでの二本指や同時操作のストレスが減る。
- 露光途中を可視化するのは通常の写真機とは異なる。そのため「霊感式カメラ」という設定と、最初の幽霊での自然な学習が必要。
- 1室しかないため、照明・小物・速度パターンの変化によって幕の違いを作る必要がある。飽きるようなら演出を増やすが、自由移動を増やして解決しない。
- 機械式シャッターの描画を優先する。ただし物理エンジンで実際の羽根の衝突まで再現する必要はない。視覚と音の反応を優先する。
- 写真と評価が露光中に見えたものとずれると遊びが壊れる。描画と評価の元データを共通化する。
- 露光最適値、視点感度、閉鎖の時間は実機での評価前の暫定値。結果次第で現行仕様を更新する。

## 後で判断し直す条件

最初の幽霊を触れるプロトタイプが完成した時に、(a)閉じる動作に反復したくなる魅力がない、(b)速度による撮り分けが視覚的に分からない、(c)固定視点では探索が退屈、のいずれかが確認されたらこの判断を再評価する。変更時は本ADRを上書きせず新ADRで置換理由を記録する。
