# 制作計画 / LONG EXPOSURE

更新：2026-10-30。状態：**設計確定案、未実装**。ゴールは「48時間ジャムの期限前に、スマホ縦画面で3体を撮影し、アルバムとエンディングまで到達できるHTML5ゲームをitch.ioへ提出する」。

## 完了条件（利用者の操作で判定）

1. 初見プレイヤーが説明を延々読まずに1体目を撮影できる。
2. 長押し中に霊が浮かび、離した瞬間に写真内容が決まり、6枚の羽根が閉じる。
3. 速い霊と遅い霊に同じシャッター時間を使い続けると不利になることが、失敗写真から分かる。
4. 3体の撮影、3枚の実際のゲーム内写真、最終演出、リプレイまで到達できる。
5. タッチ連打、キャンセル、タブ切替、回転、セーフエリアで操作不能にならない。
6. iPhone SafariとAndroid Chrome（実機を使える範囲）・デスクトップでブラウザプレイし、itch.ioにアップロードした**提出物**で確認する。

## 制作順（完成した現物が増える単位）

| 段階 | 完成させるもの | 次へ進む判定 |
|---|---|---|
| P0 操作の核 | 縦画面、暗い教室、カメラの視点移動、長押し露光、離して閉じる6枚羽根 | 指を離した瞬間に結果が確定し、繰り返しても快適 |
| P1 撮影がゲームになる | ゆっくり動く幽霊、露光の蓄積と残像、写真と鮮明度評価、即リトライ | 早すぎ・遅すぎの写真が異なり、プレイヤーが理由を理解できる |
| P2 3幕 | 速い霊と接近霊、3枚アルバム、短いオチ、リプレイ | スタートからエンドまでスマホで通しプレイ可能 |
| P3 ジャム仕上げ | シャッター音・環境音・画面演出、パフォーマンス調整、音OFF、説明、itch.io提出パッケージ | 実機・アップロード済みHTML5を通し検証 |

## 実装順の具体

1. Vite + TypeScript + Three.jsで縦画面を立ち上げ、オフラインで遊べる1ページにする。
2. Pointerイベントで押下・解放を直接管理。キャンセル・タブ非表示・回転で中断して入力ロックを防ぐ。
3. 被写体の移動を時刻から再現する関数として実装し、露光中に同じ履歴データでプレビュー・写真・判定を作る。
4. 撮影時点のゲーム画面（シーン＋露光レイヤー）を確定して画像化。UI・金属羽根は写真へ混ぜない。
5. 1体目でゲームフィールを調整してから2・3体目を足す。音とフィードバックを後回しにしすぎない。
6. 締切前にビルドをアップロードし、**itch.ioに埋め込まれた状態**のタッチ操作を確認する。

## 削る順番（時間切れ対策）

先に削る：高度な実時間反射、背景の細部、カメラ機種選択、被写体以外の登場人物、追加の部屋、実在のフィルム再現、リッチな写真アルバムUI、スコア共有。

削れない：長押し・解放の反応、速度別の撮り分け、シャッター羽根の閉鎖、撮影結果が実画面と一致、3幕の最低限の進行、リトライ、縦画面タッチ動作。

**非常時の成立ライン**：1部屋、幽霊2種、撮影→写真→エンディングの通し体験。実装途中で削る場合は仕様書のゴールも更新して、少ないが完成したゲームを出す。

## 実物での合格・不合格

- 10回続けてシャッターを切り、押していないのに露光が続く、解放が遅れる、重複撮影、写真内容のズレが1度も起きない。
- 初見プレイヤーが「長押しで姿が浮かぶ」「離して撮る」を自力で理解できるか。人がいなければ本人が説明なし条件で実機確認し、未検証を明記。
- 早い写真／適切な写真／露光しすぎた写真が同じ幽霊で明確に区別でき、最初の霊は数回以内に成功できる。
- 疾走霊は長い露光よりも短い露光が有利になる。接近霊は待ちすぎると自動閉鎖で失敗する。
- 3〜6分程度で完走でき、失敗時の再挑戦までが短い。写真を表示して次へ進む操作に迷わない。
- 720×1280相当の縦画面でUIが欠けない。実機で30fps以上を目安（端末差は記録）。
- 実機で音あり／音なし、他アプリ復帰、スクロール・長押しメニュー抑止、セーフエリア、非対応向きの表示を検証する。

## 未検証で、プロトタイプで決める値

- 露光最適時間（初期案は遅い霊 1.0〜1.6秒、速い霊 0.25〜0.55秒、接近霊 0.5〜0.9秒）
- 露光中の残像の濃度と判定閾値、シャッター開閉の体感速度、写真表示時間
- 低性能スマホでの写真キャプチャー方式とピクセル比
- 視点移動のドラッグ感度・慣性、探索ヒントの目立ち方

調整値は仕様に初期値を置き、**プレイの手触りを見て更新**する。設計時の数値を検証結果とは扱わない。
